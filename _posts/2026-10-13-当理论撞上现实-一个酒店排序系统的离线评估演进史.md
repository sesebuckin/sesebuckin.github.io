## 一、NDCG 是什么？为什么排序系统需要它

做酒店搜索排序，绕不开一个问题：**怎么衡量模型排得好不好？**

准确率、召回率把结果当"集合"看，不关心顺序。但用户只看前几个结果，第 1 位的价值远大于第 10 位。这时候就需要 NDCG（Normalized Discounted Cumulative Gain，归一化折损累计增益）。

它的核心思想其实很朴素，就三件事：

**1. 相关性是分级的，不是非黑即白**

酒店场景里，用户的行为天然分层：
- 下单 = 强正反馈
- 点击未下单 = 弱正反馈
- 曝光未点击 = 负反馈

**2. 位置越靠后，价值越低**

排在第 1 位的结果价值最高，越往后递减。用户很少翻到第 5 页。

**3. 用"理想排序"做归一化**

不同查询的满分不一样。有的查询有很多完美结果，有的本身就没有完美结果。用"把所有结果按相关性从高到低排"的理想得分作为分母，实际得分除以它，得到 0~1 之间的 NDCG。

> **一句话总结**：NDCG = 实际排序的加权相关性得分 ÷ 理想排序的加权相关性得分。1 表示完美排序。

## 二、理论很丰满：在酒店排序系统里落地 NDCG 的完整流程

理论上，在工业级酒店排序系统里离线应用 NDCG，流程是这样的：

1. **准备评估数据**：从线上日志采样带标注的查询-结果对
2. **定义相关性等级**：用行为分层（下单=3、收藏=2、点击=1、曝光未点击=0）
3. **确定评估样本集**：采样真实查询，覆盖头部和长尾，冻结测试集
4. **构造理想排序**：每个查询的候选按相关性从高到低排
5. **模型打分排序**：对同一批查询的候选打分，得到实际排序
6. **计算 NDCG@K 并聚合**：按查询分组算，再跨查询平均
7. **结果解读与迭代**：分桶分析，对比新旧模型

看起来清晰、可操作，对吧？

**但真正落地时，问题一个接一个冒出来。**

## 三、现实很骨感：四个让我卡住的疑问

### 疑问 1：Step 1-2 还好，Step 3 卡在数据质量

采样一批查询看起来简单，但真正麻烦的是：标注数据从哪来？人工标注贵且一致性差，行为日志又有位置偏差和稀疏性。热门城市样本多，长尾城市样本少，平均下来指标被头部主导。

### 疑问 2：Step 4 是最难、最贵的

一次用户的搜索可能只有城市、入离日期等硬约束，召回结果已经满足这些约束。那**所有酒店按道理都相关**，但价格、星级、位置差异巨大，怎么定义相关大小？

靠人工标注？主观、有偏见、成本高。靠规则？规则本身也是人拍的。

### 疑问 3：模型对 query 打分也难

当下训练是混合了多个查询的样本，评估时怎么对单个查询打分排序？

> **澄清**：评估时模型不是"对 query 打分"，而是对 (query, hotel) 对打分，然后对**同一个 query 下的候选酒店**按分数排序。这跟训练混合多 query 不矛盾——**模型是 pointwise 的，评估是 listwise 的**。

### 疑问 4：人工偏见无法归纳每个人的喜好

这是最本质的担忧：如果理想排序是几个工程师拍脑袋定的，它凭什么是"理想"的？

**核心认知转变**：离线 NDCG 不是"测量真实相关性"的尺子，而是"在固定条件下比较模型"的天平。它的价值不在于绝对正确，而在于**一致性和可比性**。

## 四、折衷方案：AUC 为主，NDCG 为辅

基于以上顾虑，我想到一个折衷方案：

- **AUC 作为基础离线评估指标**（主）
- **NDCG 作为辅助离线评估指标**（辅）

NDCG 的计算规则简化：

- 不考虑未曝光样本
- 有曝光的样本里：未点击 = 0，点击未下单 = 1，点击且下单 = 2
- 模型离线评估时，计算 NDCG@K

具体计算流程：

1. 评估集只保留**有曝光**的 (query, hotel) 对
2. 按行为映射相关性标签（0/1/2）
3. 模型对每条记录打分
4. **按 query 分组**：
   - 按模型分数降序 → 算 DCG@K
   - 按相关性降序 → 算 IDCG@K
   - NDCG@K = DCG / IDCG
5. 跨 query 聚合（简单平均或流量加权）
6. 与 AUC 联合决策

> **核心公式**：DCG@K = Σ (2^rel_i - 1) / log2(i + 1)

这个方案看起来平衡了成本和价值。

## 五、新问题：为什么要冻结评估集？理想排序怎么构造？

### 问题 1：冻结固定集合，和验证集测 AUC 有什么区别？

本质上是同一件事，但"冻结"在离线评估里更强调**可复现性**和**跨模型可比性**。

需要冻结三样东西：
1. **评估 query 集固定**：否则这次抽样偏热门，下次偏长尾，没法比
2. **候选集固定**：用同一份召回快照，否则候选池变了，NDCG 没法比
3. **相关性标签固定**：标准答案变了，比较无意义

**和验证集测 AUC 的关键差异在"候选集"**：

- AUC 验证集里，每个样本独立，模型只需学会"正样本高分、负样本低分"
- NDCG 必须还原"同一个 query 下有哪些候选、模型把它们排成什么样"

> **一句话**：冻结 = 保证"唯一变量是模型"。

### 问题 2：多个同级样本，理想排序怎么排？

假设一个查询下有 3 个下单酒店，label 都是 2。理想排序里谁第一？如果随机排，IDCG 每次算出来可能不同，指标不稳定。

**解决方案：用业务先验构造"同级内的二级排序"**。

举例：三个下单酒店，价格、星级、距离各不相同。可以设计优先级规则：

- **方案一**：价格匹配度优先
- **方案二**：位置 + 星级综合
- **方案三**：多维度加权打分

**关键原则**：
- 同级内排序规则要固定，所有查询用同一套
- 规则要贴近业务目标
- 规则本身有主观性，但可接受——只要对所有模型一致
- 兜底策略：无法区分的用稳定排序

> **本质**：这不是"作弊"，而是让 IDCG 更准确地反映"什么是真正理想的排序"。

## 六、更深的担忧：标准是人拍的，改了怎么办？

这是离线评估最本质的矛盾：**如果标准答案本身是人拍的、可能错的，那用它算出来的 NDCG 还有意义吗？**

### 三层回答

**第一层：所有离线指标都依赖人为定义**

AUC 的"正样本"定义（点击算正？下单算正？）也是人定的。区别只是 NDCG 的定义空间更大，改动的可能性更高。

**第二层：修改标准后，前后指标不可直接比**

解决方案是**回溯重算**：用新标准把所有历史模型重跑一遍，比较"同标准下的相对提升"，而不是绝对值变化。标准要**版本化**，像代码一样管理。

**第三层：NDCG 依赖人工经验，但可以演进**

从"拍脑袋"到"数据驱动"的演进路径：

1. **阶段一**：人工经验定义规则（初期）
2. **阶段二**：用数据校准人工规则（逆序检验、行为对照）
3. **阶段三**：用模型学习"理想排序"
4. **阶段四**：用线上 A/B 反过来校准离线标准

> **核心认知**：离线评估不需要归纳每个人的喜好，只需要一个**对所有用户平均而言合理的排序标准**。个体差异由线上模型去处理。

## 七、方案对比：只看 AUC vs AUC + NDCG

| 维度 | 方案 1（只看 AUC） | 方案 2（AUC + NDCG@K） |
|------|-------------------|----------------------|
| 离线评估开发成本 | 低 | 高 |
| 维护成本 | 低 | 高 |
| 头部排序敏感度 | 低 | 高 |
| 决策速度 | 快 | 慢 |
| 与线上对齐难度 | 低 | 中 |
| 团队认知门槛 | 低 | 高 |
| 长期演进潜力 | 中 | 高 |

### 方案 1 的优势

- 开发成本极低，复用训练流程
- 无人工偏见风险
- 团队沟通成本低
- 决策链路短

### 方案 1 的劣势

- 对头部排序不敏感
- 无法反映列表结构质量
- 正负样本定义掩盖等级信息
- 可能被简单样本主导

### 方案 2 的优势

- 直接衡量头部排序质量
- 支持分级相关性
- 与业务目标更贴近
- 长期演进潜力大

### 方案 2 的劣势

- 开发成本高，维护成本高
- 人工偏见风险
- 可能和线上指标脱节
- 决策复杂度上升

> **最终建议**：资源紧、迭代快、AB 成熟 → 方案 1；资源足、追求精细、头部敏感 → 方案 2；不确定 → 先方案 1，用轻量 NDCG 验证后再决定。

## 八、我的改进：监控线上 top-K 指标

实际中我采用了**监控线上 top-K 的点击比、下单比**指标。这是对方案 1 的重要补强。

### 补上了什么

方案 1 最大的问题是 AUC 对头部排序不敏感。top-K 点击比/下单比**直接衡量头部质量**，而且用的是**真实用户行为**，比离线 NDCG 更贴近业务真相。

### 但要分清：线上 top-K ≠ 离线 NDCG

| 维度 | 线上 top-K | 离线 NDCG@K |
|------|-----------|-------------|
| 观测时机 | 上线后 | 上线前 |
| 数据来源 | 真实行为 | 历史/标注 |
| 作用 | **验证**模型 | **预测**模型 |

**你的做法没有替代离线 NDCG 的核心功能**——它不能帮你在上线前筛选模型，只能事后验证。

### 还有什么没解决

1. 离线阶段仍无法筛选头部优化
2. top-K 指标的 K 和分母定义要小心
3. 仍受位置偏差影响
4. 无法诊断"为什么头部变差"
5. 长尾 query 的头部质量被平均掩盖

> **定位**：你的做法不是替代离线 NDCG，而是把头部质量的观测从离线搬到了线上。

## 九、团队条件：快速迭代、上线便宜，方案 1+ 更香？

**是的，在"快速迭代 + 实验上线成本低"的团队里，方案 1+ 很有优势。**

### 核心逻辑

离线指标存在的根本理由是"上线验证很贵"。如果上线便宜，离线筛选的边际价值就下降了——**你不需要花大力气预测哪个模型好，直接上线测就行了**。

### 优势

1. 省掉了最贵的部分：离线评估体系的建设与维护
2. 决策依据更真实（真实用户行为，无人工偏见）
3. 迭代闭环更短
4. 团队认知负担低
5. 避免"离线涨线上不涨"的信任危机

### 但优势成立有前提

- AB 实验确实"便宜且快"
- AB 资源不是瓶颈
- 模型迭代方向明确
- 线上指标足够敏感
- 候选模型数量可控

### 边界：什么时候不够用

- 无法定位"为什么"
- 长尾问题被平均掩盖
- 无法做反事实分析
- AB 实验有不可逆风险
- 长期评估能力缺失

> **务实建议**：方案 1+ 作为主干，低成本补充少量离线能力（极简头部指标、线上分桶、评估集快照）。

## 十、终极约束：只有一个工程师怎么办？

如果这个大型项目**只有一个工程师负责全链路开发**，同时还要维护其他项目——**明确支持方案 1+**。

### 为什么方案 2 是"负资产"

1. **建造成本会挤占真正重要的事**：不是两周能搞完，而是持续几个月
2. **维护成本会持续吸血**：线上在变、业务在变、模型在迭代
3. **认知负担和沟通成本翻倍**：没有第二个人分担
4. **一旦离职或转岗，体系直接荒废**：单点维护，没有冗余

### 方案 1+ 的优势被放大

1. 复用现有基础设施，几乎零额外开发
2. 维护成本趋近于零
3. 决策链路短，适合"一个人扛"
4. 用"真相"替代"预测"，绕过认知瓶颈
5. 风险可控

### 但单工程师要补三个短板

1. **诊断能力弱** → AB 指标分桶看，每周抽 bad case
2. **无历史基线** → 冻结一份评估集快照（低成本期权）
3. **单点风险** → 文档化评估逻辑

> **核心原则**：对单工程师，减负比精细更重要。最危险的选择，是让一个已经满负荷的工程师，去维护一套她没精力维护的精密评估体系。

## 十一、最后的领悟：工业界没有标准答案

走完这一路，我最大的领悟是：

> **对于一个实际工业界的推荐项目如何设计，可能有理论技术标准答案，但实际操作时永远没有一个标准答案。最后一定是要权衡资源、人力、成本，做出一个相对较好的系统，这个系统可能并不完美。**

### 为什么"没有标准答案"是必然的

工业系统不是有唯一解的数学题，而是**多目标约束优化问题**：

- 约束是动态的
- 目标本身是模糊的
- 变量互相耦合
- 信息永远不完全

### 理论答案 vs 实际答案

| 维度 | 理论标准答案 | 实际工程答案 |
|------|-------------|-------------|
| 前提 | 资源无限 | 资源有限 |
| 目标 | 单一最优 | 多目标权衡 |
| 视角 | 静态理想 | 动态演进 |
| 评价 | "是否最优" | "是否够好、可落地、可持续" |

**理论告诉你天花板在哪，现实告诉你这一步能走到哪。**

### 接受"不完美" ≠ "随便做"

| 接受不完美 | 随便做 |
|-----------|--------|
| 明确知道哪里不完美 | 不知道哪里有问题 |
| 知道为什么不完美 | 没有约束意识 |
| 知道未来怎么补 | 没有演进计划 |
| 核心目标达成 | 核心目标也含糊 |
| 主动取舍 | 被动妥协 |

### 好的工程师 vs 优秀的工程师

> **好的工程师追求"最优解"，优秀的工程师追求"在约束下可持续演进的解"。**

---

## 写在最后

这篇文章记录的不是一个"最佳实践"，而是一次真实的方案权衡过程。从追求 NDCG 的理论完备，到接受 AUC + 线上 top-K 的务实方案，每一步都不是"理论最优"，但每一步都是"当下最合适"。

如果你也在做类似的决策，希望这篇文章能给你一点参考：

- **永远先问约束**，再谈方案
- **保留理论天花板意识**，但不必追求最优
- **为演进留余地**，每个方案都问"未来升级成本高不高"
- **记录决策理由**，未来复盘用
- **接受被推翻**，条件变了，答案就该变

工业界没有标准答案，只有"在当下约束下相对较好的解"。接受这一点，不是妥协，而是清醒。
